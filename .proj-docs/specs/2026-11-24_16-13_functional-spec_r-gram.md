## 背景及目標

R Gram 係一個自用嘅 fan-made PWA，介面係一部經典唱片機，專門播香港樂隊 RubberBand 嘅專輯。播放端設計已經完成（HANDOFF v16），但設計階段冇處理三樣嘢：

1. 聲音同 MV 由邊度嚟
2. 封面、歌單、歌詞由邊個、喺邊度管理
3. 歌詞點顯示

今次要做嘅係一個完整產品：

| 部分 | 目標 |
| --- | --- |
| 播放端（Frontend PWA） | 按 HANDOFF 實作唱片機介面，播 R2 上面嘅音檔同 MV，顯示跟歌同步嘅歌詞 |
| 管理端（Backend + Admin） | Login 之後管理專輯封面、歌單、歌詞，將 R2 專輯資料夾入面嘅音檔 / MV 檔配對去歌曲，發佈畀播放端 |
| 媒體儲存 | 音檔同 MV 檔放 Cloudflare R2，按專輯分資料夾 |

| 項目 | 內容 |

## 驗收標準

整體驗收（超出個別 US）：

1. 用戶喺 iPhone 安裝 PWA，由冷啟動行完：旗幟 → 主頁 → 開 Wheel 轉碟 → 入歌單 → 播歌 → 睇歌詞 → 睇 MV → stop → 繼續播歌，全程冇卡住、冇錯位，畫面同 `_mockups_/r-gram/index.html` 對應格一致
2. 管理員由 login 行完：改一張專輯嘅封面 → 掃描 R2 資料夾 → 貼一首歌嘅 LRC → 發佈；播放端重新開啟後見到新封面、播到新配對嘅歌、睇到新歌詞
3. 未登入或者非白名單帳戶改唔到任何內容
4. 播放端由 vN 自動更新去 vN+1 驗證通過
5. 開咗「減少動態效果」行一次第 1 項流程，冇大幅度動畫
6. 所有 4–5 步流程（US-005、US-106）嘅理由同簡化方案已記錄喺本文件
7. 新畫面（歌詞、Info、管理端）喺寫 code 之前已有用戶確認嘅 mockup

## Design Proposal

> 以下只係方向提案。按團隊 Preview-First 規則，每個都要先做靜態 HTML preview（`_mockups_/<feature>/index.html`）畀用戶確認，先可以寫 UI code。

### P-1 歌詞畫面 + 歌詞掣

- **入口**：左下掣列加第四粒掣（同一款拉絲鋁，x = 538，同其他三粒相隔 138），icon 係幾行文字；開咗外圈著燈；冇歌詞時變灰
- **畫面**：唱片機同標題變模糊再壓暗（沿用歌單頁嘅黑底白字），歌繼續播
- **歌詞**：直排一列置中偏左；而家唱緊嗰行白色、字級 42（Noto Sans HK 700），左邊有專輯色短橫線；其他行字級 32，越遠越淡（同歌單一樣嘅遠近處理）
- **動態**：換行時向上捲一行（≤ 300ms）；reduced-motion 直接切換
- **收返**：再㩒歌詞掣；掣列喺歌詞層上面保持可見

```
┌──────────────────────────┐
│ 碟名            v0.1.0   │  ← 模糊 + 壓暗
│ 2008 ──                  │
│ 歌名                     │
│                          │
│      上兩行（好淡）      │
│      上一行（淡）        │
│ ── 而家唱緊嗰行（白）    │  ← 專輯色短橫線
│      下一行（淡）        │
│      下兩行（好淡）      │
│                          │
│ (i) (♥) (MV) (詞)        │  ← 歌詞掣著燈
└──────────────────────────┘
```

### P-2 Info 畫面

- **入口**：Info 掣（開咗外圈著燈）
- **畫面**：同 P-1 一樣嘅模糊 + 壓暗層；歌照播
- **內容**（由上到下）：碟名（Lubalin 大字）→ 專輯色橫線 → 發行日期、類型、唱片公司、歌曲數目（細字標籤 + 值）→（揀咗歌先有）歌名 → 曲、詞、編、監四行（標籤用單字，值用 Noto Sans HK）→ 底部 `R Gram v0.1.0` + 一行「Fan-made，非官方」
- **收返**：再㩒 Info 掣

### P-4 主頁改版：似一部唱片機（✅ C10）

- **問題**：v16 主頁係一隻出界嘅大碟加浮喺上面嘅掣，左下掣列（特別係 MV 掣）疊住碟邊；整體唔似一部唱片機
- **方向**（要出 2–3 個方案畀用戶揀）：
    - 有一個機身（plinth）嘅概念：轉盤（platter）、唱臂、掣都坐喺機身上面，各有自己位置，互不重疊
    - 掣列搬去機身嘅操作區（例如機身底邊一行），同轉盤之間留明確間距
    - 隻碟可以縮細到成個圓喺畫面入面，或者保持局部出界，但出界嘅係機身同轉盤一齊
    - 黑白主色 + 專輯色、拉絲鋁質感、字體、左上資訊結構保持（HANDOFF §3 已確認嘅規則唔變）
- **影響**：主頁、Wheel、歌單、播放、電視、歌詞層嘅位置數字全部要跟新版面重定；歌詞掣（P-1）同播放模式掣（P-6）嘅位置一齊喺呢個修訂版解決
- **硬性條件**：任何掣連著燈光圈同 CD 之間最少留 16（1080 基準）

### P-5 收藏心形掣 + Favourites 碟（✅ C6）

- **心形掣**：主頁左上角歌名後面，同歌名同一行、垂直置中；空心 = 未收藏，實心著燈色 = 已收藏；歌名太長時歌名用「…」收尾，心形掣唔會被擠走
- **Favourites 碟**：Wheel 最後一格，標記係心形；碟面用專屬設計（建議：黑色碟面 + 白色心形，同旗幟嘅黑白 logo 呼應），強調色建議用一隻固定嘅紅
- **主頁 Favourite 掣**：㩒落去轉去 Favourites 碟（Wheel 唔使打開，隻碟直接換）；身處 Favourites 碟時外圈著燈
- **Favourites 歌單**：同專輯歌單一樣嘅弧形排列；歌號用收藏次序；冇收藏時框線位置顯示一行提示

### P-6 Shuffle / Repeat / Repeat One（✅ C7）

- **方向**：兩粒同款拉絲鋁掣（Shuffle、Repeat），放喺 P-4 新機身嘅操作區；Repeat 掣㩒一下循環三個狀態（關 → 成隻碟 → 一首，icon 加「1」）；開咗外圈著燈
- **待定**：掣數目多咗（Info、Favourite、MV、歌詞、Shuffle、Repeat 共 6 粒），要喺 P-4 一齊排位，或者將部分收入第二層

### P-7 iPhone Duo / HomeView / 電腦版面（✅ C11）

| 裝置 | 螢幕（CSS px） | 方向 |
| --- | --- | --- |
| 手機直度 | 約 390×844 | P-4 基準版面 |
| iPhone Duo 闔上・直 | 426×612 | 比手機矮：手機版面按高度重排 |
| iPhone Duo 打開・直 | 612×876 | 接近 7:10：成部唱片機可以完整顯示 |
| iPhone Duo 打開・橫 | 876×612 | 摺位喺正中：左邊唱片機、右邊歌單 / 歌詞 / 電視，內容避開摺位 |
| HomeView | 544×544 | 正方形：成部唱片機俯視圖置中，歌單同歌詞用覆蓋層 |
| 電腦 | ≥ 1024 闊 | 橫向：唱片機置中或者靠左，旁邊常駐歌單 / 歌詞；滑鼠同鍵盤操作 |

- 每種裝置一份 mockup，逐份確認；次序：手機 → Duo → HomeView → 電腦

### P-3 管理端

- **方向**：沿用 903-player `apps/admin` 嘅視覺語言同元件做法（分段 tab、圖片格 + 裁切對話框、儲存條、Toast、確認對話框）；桌面為主，手機可用；介面文字用書面語
- **畫面**：

    | 畫面 | 內容 |
    | --- | --- |
    | 登入 | 「以 Google 登入」掣；冇權限頁 |
    | 專輯列表 | 封面縮圖、碟名、年份、Wheel 字母、上架掣、完整度；拖動排序；未發佈修改提示 + 發佈掣 |
    | 專輯頁 | Tab：資料（欄位 + 封面 + 專輯色 + 圓碟預覽）｜歌單（歌曲表 + 掃描掣 + 每首歌嘅音檔 / MV / 歌詞狀態）|
    | 歌詞編輯 | 左：LRC 文字框 + 逐行驗證；右：播放預覽（P1）；儲存 / 清除 / 由同名歌複製 |
    | 掃描結果 | 已配對、配對唔到嘅檔案、未有檔案嘅歌；手動指定 |
    | 發佈確認 | 變更摘要 + 警告 + 確認；發佈記錄（P1） |
