## 背景及目標

R Gram 係一個自用嘅 fan-made PWA，介面係一部經典唱片機，專門播香港樂隊 RubberBand 嘅專輯。播放端設計已經完成（HANDOFF v16），但設計階段冇處理三樣嘢：

1. 聲音同 MV 由邊度嚟
2. 封面、歌單、歌詞由邊個、喺邊度管理
3. 歌詞點顯示

今次要做嘅係一個完整產品：

| 部分 | 目標 |
| --- | --- |
| 播放端（Frontend PWA） | 按 HANDOFF 實作唱片機介面，播 R2 上面嘅音檔同 MV，顯示跟歌同步嘅歌詞 |
| 管理端（Backend + Admin） | Login 之後管理專輯封面、歌單、歌詞，將 R2 專輯資料夾入面嘅音檔 / MV 檔配對去歌曲；每次儲存即時喺播放端生效（CR-003：冇草稿、冇發佈） |
| 媒體儲存 | 音檔同 MV 檔放 Cloudflare R2，按專輯分資料夾 |

#### 播放模式（合併 Shuffle 同 Repeat）

| 項目 | 內容 |
| --- | --- |
| 掣 | 一粒；每㩒一下轉一個：順序 → 重覆全部 → 重覆一首 → 隨機 |

| 儲存 | 本機，重開 app 保持 |

#### D31 歌曲文字格式（已確認：由決定 8、D32、D37 完全決定）

```
歌名
副題：…
曲：…
詞：…
編：…
監：…

[00:12.30]第一句歌詞
[00:18.75]第二句歌詞
```

| 部分 | 規則 |
| --- | --- |
| 歌名 | 第一個非空白行；必填。時間標記開頭嘅行唔可以做歌名（防止淨係貼咗 LRC） |
| 曲詞編監 | 標籤 `曲`／`詞`／`編`／`監` + 全形或者半形冒號；次序隨意；每項可以冇；每項最多一次（重覆 = 嗰行報錯）；值係自由文字 |
| 副題 | `副題：`，規則同上（D37） |
| 呢一段幾時完 | 遇到第一個空行，或者第一行唔係標籤行嘅行 |
| 歌詞 | 之後全部；可以冇 |
| 時間標記 | D32 |
| 歌號 | 唔喺文字入面：跟歌曲行嘅次序（拖動排序會重編） |
| 回填 | 文字框永遠由已儲存嘅資料用同一個格式砌返出嚟（次序固定：副題、曲、詞、編、監；全形冒號；冇值嘅項目唔出），所以「讀入 → 儲存 → 再讀入」唔會變 |
| 錯誤 | 逐行指出（行號 + 原因），顯示喺文字框旁邊嘅檢查結果；有錯就儲存唔到 |

介面文字例子（書面語）：「第一行必須是歌名」「第 3 行：「詞」重複出現」「第 9 行沒有時間標記（其他歌詞行都有）。請補上，或者全部歌詞都不加時間標記。」「儲存後會清除這首歌現有的歌詞，確定要繼續嗎？」「已儲存，播放端已更新」。

## 驗收標準

整體驗收（超出個別 US）：

1. 用戶喺 iPhone 安裝 PWA，由冷啟動行完：旗幟 → 主頁 → 開 Wheel 轉碟 → 入歌單 → 播歌 → 睇歌詞 → 睇 MV → stop → 繼續播歌，全程冇卡住、冇錯位，畫面同 `_mockups_/r-gram/index.html` 對應格一致

3. 未登入或者非白名單帳戶改唔到任何內容
4. 播放端由 vN 自動更新去 vN+1 驗證通過
5. 開咗「減少動態效果」行一次第 1 項流程，冇大幅度動畫
6. 所有 4–5 步流程（US-005、US-106）嘅理由同簡化方案已記錄喺本文件
7. 新畫面（歌詞、Info、管理端）喺寫 code 之前已有用戶確認嘅 mockup

### P-1 歌詞畫面 + 歌詞掣

> ⚠️ 已取代：CR-002 將歌詞併入歌書；歌詞版面以播放端設計稿第 17 版為準（§CR-003「歌書歌詞版面」，用戶 2026-11-25 確認）。下面只留做記錄。

- **入口**：左下掣列加第四粒掣（同一款拉絲鋁，x = 538，同其他三粒相隔 138），icon 係幾行文字；開咗外圈著燈；冇歌詞時變灰
- **畫面**：唱片機同標題變模糊再壓暗（沿用歌單頁嘅黑底白字），歌繼續播
- **歌詞**：直排一列置中偏左；而家唱緊嗰行白色、字級 42（Noto Sans HK 700），左邊有專輯色短橫線；其他行字級 32，越遠越淡（同歌單一樣嘅遠近處理）
- **動態**：換行時向上捲一行（≤ 300ms）；reduced-motion 直接切換
- **收返**：再㩒歌詞掣；掣列喺歌詞層上面保持可見
