# Test Plan — api-auth

- Chain: Backend 基礎同登入（`apps/api`）：Hono Worker、env 驗證、D1 migration（6 張表）、health、Google 登入（PKCE）、email 白名單、session、`/api` 守門、登出。任務 T-020、T-021
- AC（L1 來源：TS = Technical Spec、FS = Functional Spec、Plan = Implementation Plan）:
    - AC-1 白名單（FS US-101 第 1 點；TS「安全設計」認證、授權）：只有 `ADMIN_EMAILS` 入面、Google 已驗證嘅 email 開到 session；其他帳戶見到「沒有權限」頁，唔開 session
    - AC-2 未登入（FS US-101 第 2 點；TS「API 設計」通則）：`/api/*`（`health` 除外）一律 401 `UNAUTHORIZED`
    - AC-3 登出同期限（FS US-101 第 3 點；TS「安全設計」Session）：登出刪 session 兼清 cookie；session 30 日過期；32 bytes 隨機 token，D1 只存 SHA-256；cookie `__Host-session`：`HttpOnly; Secure; SameSite=Lax; Path=/`
    - AC-4 返回原頁（FS US-101 第 4 點；TS「安全設計」`next` 參數）：登入後去 `next`；只收同站相對 path，其他一律當 `/`
    - AC-5 OAuth（TS API-001、API-002；「安全設計」認證）：Authorization Code + PKCE S256；`state` + verifier 喺短期 `__Host-oauth` cookie；callback 驗 issuer、audience、`email_verified`
    - AC-6 CSRF 同 header（TS「安全設計」CSRF、Header、搜尋引擎）：改資料嘅 method 要 `Origin` = `WORKER_ORIGIN`，唔啱 403 `FORBIDDEN_ORIGIN`；`/api`、`/auth` 有 `X-Frame-Options: DENY`、`frame-ancestors 'none'`、`Cache-Control: no-store`；所有回應 `X-Robots-Tag: noindex`
    - AC-8 補充（CR-004，T-098；TS「數據庫設計 → albums」）：`albums.category` NOT NULL + CHECK 六個值、`category_no` NOT NULL + CHECK ≥ 1、`cover_source_etag`；`tracks.text_source_etag`；仍然只有 `0001_init.sql`。CR-005（T-100；TS「數據庫設計 → albums」）：`cover2`、`thumb2`（FK → `assets`）、`cover2_source_etag`；CHECK `cover2 IS NULL OR cover IS NOT NULL`（插入同清走第一張都擋）。CR-006（T-101、T-102；TS「CR-006 → 已完成嘅 code 要改嘅地方」schema 行）：`albums` 冇 `release_date`、`type`，`year` 留（NULL = 冇）；`tracks."no"` CHECK 1–999；API-023 由 session 守門清單拎走。T-025：API-030、API-031、API-032 加入守門清單（`sessionGuard.test.ts`）；`config.ts` 加 `SCAN_*` 常數；`package.json` 加 `seed`、`seed:sql`（屬 `api-seed` 嘅 script）同 `esbuild` devDependency
    - AC-10 CR-007（T-104 – T-106；TS v1.7「資料模型」「API 一覽嘅變化」「安全設計（CR-007 補充）」）：`albums` 冇 `label`／`wheel_key`／`sort_order`，加 `info_etag`、`info_used`（0／1，W-046）、`checks`（JSON array），`folder` NOT NULL UNIQUE；`tracks` 冇 `subtitle`、手動指定、參考欄，加 `text_key`；API-011、013 – 015、020 – 022、030 – 032 → 404（`test/removedRoutes.test.ts`）；API-017 – 019、033 – 035、040、041 喺 session + same-origin 之後（`sessionGuard.test.ts`）；`package.json` 冇 `seed`、`seed:sql`、`esbuild`；`wrangler.toml` 註解：Worker 只寫 `info.txt`、`NN ….txt`，唔刪
    - AC-7 Health 同錯誤格式（TS API-004、API-005；「API 設計」錯誤格式）：`GET /api/health` → `{ ok, version }`（version = `apps/api/package.json`）；`GET /api/me` → `{ email }`；錯誤係 `{ error: { code, message } }`
    - AC-8 資料庫（TS v1.2「數據庫設計」「索引設計」，CR-003）：`albums`、`tracks`、`lyrics`、`assets`、`catalog_state`、`sessions` 嘅欄位、約束同四個索引（冇 `enabled`、冇 `publishes`）
    - AC-9 設定（Plan T-020；TS「部署架構」Bindings、`[vars]`；「安全設計」Secret）：`DB` / `CATALOG` / `MEDIA`、五個 var、兩個 secret；漏咗或者格式錯一律 500，log 只記名；secret 唔入 repo
    - AC-11 部署準備（T-116 A6、D108；review S-234）：`[assets]` = `../admin/dist`、SPA fallback、`run_worker_first` = `/api/*`、`/auth/*`、`/catalog/*`（呢三個 prefix 永遠由 Worker 答，未知 path = API 嘅 JSON 錯誤）；`ADMIN_EMAILS` 係 secret：`validateEnv` 冇設、空、空白 = 全部 500（fail closed），唔喺白名單嘅 session = 401；`wrangler.toml` 填用戶嘅值、冇 `ADMIN_EMAILS`；`scripts/check-deploy-config.mjs`（+ `toml-keys.mjs`）擋全 0 id、placeholder client id、example／localhost、任何寫法嘅 `ADMIN_EMAILS` key；`migrate:remote`、`deploy` 前自動行；`test/deployConfig.test.ts`
