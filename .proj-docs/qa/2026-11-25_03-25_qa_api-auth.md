## Findings

### 冇 🔴 / 🟡。一條 🟢 Minor（唔 block，入 backlog）：好長嘅非 ASCII `next` 令登入停喺「登入逾時」

- L1：冇違反到實際頁面。US-101「登入後返回原本想去嘅頁」同 TS「`next` 只接受同站相對 path」只喺人手砌嘅網址先受影響：管理端傳嘅係已編碼嘅 `location.pathname`（按 byte 計啱），頁面網址亦冇幾百個中文字。所以定做 Minor。
- L2：`next=/` + 330 個「樂」（991 byte，過到 2048 byte 上限）→ Chromium 冇收低 `__Host-oauth`（`name=value`：300 個字 3827 byte 有收；320 個字 4068 byte；682 個字 8412 byte），冇 cookie 嘅 callback 出 400「登入逾時」。㩒「重新登入」（冇 `next`）就登入到。
- L3：`safeNext` 用輸入嘅 UTF-8 byte 數做上限，但放入 cookie 嘅係 URL parser 編碼後嘅字串（每個中文字 9 個字元），再加 base64。上限應該按回傳嗰條字串計（review S-027 原本嘅建議）。

## 建議補測（高風險邏輯，≤ 3；由 developer 寫）

- `test/oauthHelpers.ts` 嘅 `encodeJson` 用 `btoa`，遇到非 Latin-1 字元會 throw，所以而家冇辦法經 callback 測非 ASCII email（W-008 只有 `isAdminEmail` 嘅 unit test）。改做 UTF-8 安全，加一個 callback test：白名單 `kelvin@…`、id_token email 用 U+212A → 403、冇 session（probe 驗過）。
