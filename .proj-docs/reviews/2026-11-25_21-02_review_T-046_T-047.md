### W-032 封面冇 Service Worker runtime cache，預載咗嘅第二張封面離線時用唔到（要決定邊個任務做）

- **位置**：`apps/player/vite.config.ts:98`（`runtimeCaching` 只有字體）；`apps/player/src/catalog/usePrefetchOtherArt.ts:15-19`
- **L1**：FR-042「兩張都入離線 cache」；Functional Spec D56「離線」一行；Technical Spec 第 1228 行寫「封面已經係 CacheFirst runtime cache」（第 709 行亦有設計），但而家 code 入面冇呢條規則
- **L2**：`grep runtimeCaching apps/player` 只搵到 `remoteFontCaching(fontUrl)`。`fontSource.ts:57-58` 係唯一一條 CacheFirst，而且只對字體網址。Plan 入面亦冇任務負責「封面 runtime cache」。Developer 自己都講明咗呢個缺口
- **L3**：將來加規則嗰陣要留意兩點。① Workbox 嘅 CacheFirst 預設唔 cache opaque（status 0）回應；預載用 `mode: 'no-cors'`，攞返嚟嘅正係 opaque 回應，所以加咗規則都唔會入 cache，除非規則加 `cacheableResponse: { statuses: [0, 200] }`。② API 嘅 `/catalog/v1/img/*` 其實有回 CORS 畀 `PLAYER_ORIGINS`（`apps/api/src/catalog/routes.ts:21-28`），所以 `usePrefetchOtherArt.ts:15` 註解講「另一個 origin 所以用 no-cors」嘅理由唔成立。用 `mode: 'cors'` 就唔使 cache opaque 回應（Chrome 每個 opaque 回應會按約 7 MB 計 quota）
- **影響**：而家預載只會入 HTTP cache。離線開 app 時，第二張封面（同第一張）唔一定攞得到。FR-042 嘅離線部分未做到
- **方案 A**：喺 T-046 補一條封面 CacheFirst 規則：只對 `imageBase`，`expiration` 有上限，預載改用 `mode: 'cors'`；連 unit test（好似 `fontSource.test.ts` 咁測 urlPattern）。範圍細，而且同 T-046 嘅驗收標準直接有關
- **方案 B**：PM 開一個新任務（或者放入負責 PWA / 離線嘅任務）專做圖片同歌詞嘅 runtime cache（Technical Spec 第 709-710 行），同時改 Technical Spec 第 1228 行嘅字眼；T-046 照現狀收貨
- **推薦**：B。歌詞都要同一類規則（第 710 行），一次過做比較整齊；但無論揀邊個，都要寫低由邊個任務負責，所以標「需要用戶 / PM 決定」
