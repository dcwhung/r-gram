## 🟡 Warning

### W-012 淨係數字嘅方括號當咗時間標記：純文字歌詞同歌名無故報錯
- **位置**：`packages/catalog/src/lrc/parseLrc.ts:46`（`TIMESTAMP_LIKE = /^[\d:.]+$/`）經 `startsWithTimestamp()`（:96）用喺 `song-text/lyrics.ts:62` 同 `song-text/parseSongText.ts:49`
- **L1**：Functional Spec D31「時間標記開頭嘅行唔可以做歌名」；D32「全部都冇（時間標記）→ 純文字歌詞」。`[1]`、`[1999]` 唔係時間標記（冇 `:`）。
- **L2（實測）**：`歌名\n\n[1] 第一段\n歌詞一\n歌詞二` → `synced: true`，`[1]` 行 `BAD_TIMESTAMP`、其餘每行 `MIXED_TIMESTAMPS`，儲存唔到；`[1999] 歌\n曲：A` → `TITLE_REQUIRED` + `BAD_TIMESTAMP` + `MIXED_TIMESTAMPS`。對比 `[Chorus]` 就正確當純文字。
- **影響**：細（262 首 seed 冇呢種歌名；歌詞用 `[1]` 標段唔常見），但錯誤訊息會叫用戶「補時間標記」，誤導；有字面 spec 違反同簡單修法。
- **方案 A（推薦）**：`startsWithTimestamp()` 用一個要有冒號嘅形狀判斷（例如 `/^\d+:[\d:.]*$/`；`[00:60.00]`、`[1:2]` 照算），`parseLrc()` 自己嘅 `TIMESTAMP_LIKE` 唔郁（`[1]歌詞` 喺同步歌詞照報 `INVALID_TIMESTAMP`，現有行為不變）。加兩個測試：`[1]` 開頭嘅純文字歌詞、`[1999]` 開頭嘅歌名。
- **方案 B**：保持現狀，喺 Technical Spec 寫明「方括號入面只有數字、冒號、點 = 時間標記」。代價：同 D31 / D32 字面唔一致，要用戶接受。
