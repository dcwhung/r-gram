## Suggestion（入 backlog，唔 block）

- **S-043** `catalog/loader.ts:41-48,54-61`：回應 header 到咗、body 讀到一半超時，`response.json()` 因 abort 拋錯，喺 `readDocument` 嘅 catch 變咗 `invalid`，唔係 `timeout`（實測：stream body 卡住 8 秒 → `{ status: 'ready', failure: 'invalid' }`）。同 `:54`「abort 引致嘅錯一律當 timeout」唔符。Fallback 照啱，只係原因標籤錯。改法：`fetchDocument` 收到 `readDocument` 嘅失敗而 `controller.signal.aborted` 係 true 就回 `timeout`；加一個 stream body 卡住嘅測試。
- **S-044** `catalog/loader.test.ts:120-132`：「should not abort a request that answers in time」先 `advanceTimersByTimeAsync(8000)` 再驗 `getTimerCount() === 0`，timer 已經自己行完，所以刪走 `clearTimeout` 嘅 mutant（M1）照過。改做 `await loadCatalog()` 之後即刻驗 timer 數，或者 spy `clearTimeout`。
- **S-045** `catalog/loader.ts:51`：播放端（Vercel）同 Worker（Cloudflare）唔同網域，`ETag` 唔係 CORS safelisted response header，冇 `Access-Control-Expose-Headers: ETag` 嘅話 `headers.get('ETag')` 永遠 null，`rgram.catalog.v1` 嘅 `etag` 永遠係 null（讀 code + Fetch 規格；測試用同源 `Response` 所以捉唔到）。而家冇人讀 etag，冇行為影響。入 backlog 畀 T-026 / T-027（`catalog/serve.ts`）：expose `ETag`；另外 `Access-Control-Allow-Origin` 跟 origin 變，要加 `Vary: Origin`，否則瀏覽器 / CDN cache 會混。
- **S-046** `catalog/selectors.ts:15`、`selectors.test.ts:21`：「冇歌嘅專輯照列」引 D39（待確認）。行為本身係已確認嘅決定 7，而且係原樣傳出，冇代碼靠 D39；改引「CR-003 決定 7」，D39 只留畀 T-037 嘅「尚未有歌曲」空狀態。
- **S-047** 設定可見性：冇 `apps/player/.env.example` 列 `VITE_CATALOG_URL`（`apps/api` 有 `.dev.vars.example`）；production build 漏設時唔會有任何提示。建議加 `.env.example`，並喺 `vite.config.ts` 對 `mode === 'production'` 冇設時警告（或者 T-034 對 `notConfigured` 唔顯示重試掣）。
- **S-048** `catalog/loader.ts:74-79`：`loadCatalog`「永遠 resolve」靠 `store.write` 唔拋錯；`createCatalogStore` 做到，但 `CatalogStore` 介面冇講明，注入一個會拋嘅 store 就會 reject（實測）。喺介面註明「唔可以拋錯」，或者 loader 自己包 try。順手：`defaultDeps.test.ts:23-27` 嘅 `vi.restoreAllMocks()` 喺測試入面，斷言失敗就唔會還原，搬去 `afterEach`。
