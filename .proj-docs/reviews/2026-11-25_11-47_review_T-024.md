## 🟢 Suggestion / Observation（入 backlog，唔 block）

- **S-082** `assets/png.ts:35-46`、`assets/jpeg.ts:70-86`：結構檢查只到檔頭，比決定 4 講嘅「結構壞 → 400」窄。實測 200：PNG 只有 signature + IHDR（33 bytes，冇 IDAT / IEND）、IHDR bit depth 99；JPEG 只有 SOI + SOF（冇 SOS / EOI）、SOF3（lossless）、SOF9（arithmetic），瀏覽器多數唔識 decode 呢兩種；三種格式都收尾部多出嘅資料（PNG 後面駁 HTML → 200，出圖係 `image/png` + `nosniff`，唔會變 HTML）。只有登入咗嘅管理員上載得，唔係漏洞，影響係壞圖會入 R2。方案：PNG 行 chunk 到 IEND（驗長度唔驗 CRC）、驗 bit depth / color type；JPEG 只收 SOF0 / SOF1 / SOF2，而且 SOF 之後要搵到 SOS。或者註解同 spec 寫明「只驗檔頭同尺寸」。
- **S-083** `assets/webp.ts:121-131`：VP8X 嘅 canvas 尺寸冇同入面 VP8 / VP8L 嘅尺寸比較。實測 VP8X 寫 1200 × 1200、VP8L 實際 16 × 16 → 200，當 1200 收。動畫（`ANMF`，VP8X flag 0x02）都收，封面會郁。方案：非動畫 VP8X 要 canvas = 圖像 chunk 尺寸；動畫擋唔擋由 PM 定（spec 冇講）。
- **S-084** 測試缺口（行為實測啱，但 mutant 存活）：M1 拎走 route 上嘅 `skipPostWrite`（hook 而家係 `noPostWrite`，T-026 換咗 `rebuildCatalog()` 之後 `assetsUpload.test.ts:312` 先有用）；M5 拎走 `webp.ts:142` RIFF 長度截短檢查；M16 `webp.ts:110` 差一 byte；M17 `jpeg.ts:80` SOS 喺 SOF 之前（俾 `expected a marker` 擋咗，冇測試指定原因）；M19 `imageName.ts:11` 拎走 `^`（R2 key 係字面，`:name` 冇 `/`，所以唔會 traversal，但守門冇測試）；M20 `png.ts:38` IHDR type 檢查（俾長度檢查遮住）。M13（拎走 `requireImageType`）同 M21（`length < 0`）係等價 mutant。方案：每個加一個指定 bytes 嘅測試；名表加 `a0123456789abcdef.webp`、17 個 hex。
