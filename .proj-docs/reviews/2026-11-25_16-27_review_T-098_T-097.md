### W-028 `packages/catalog/src/schema/types.ts:49-50`、`parseCatalogDocument.ts:93-97`：`category` / `categoryNo` 係選填，同 catalog 合約唔一致

- **L1**：Technical Spec 第 521 行（API-072）寫「專輯加 `category`（六個短名之一）同 `categoryNo`（正整數）……validator 要驗」；第 1011 行寫「`albums[]` 加 `category`、`categoryNo`」。`types.ts` 自己嘅註解亦寫「Backend 生成嘅 catalog 一定有」。
- **L2**：`parseCatalogDocument.test.ts`「should still accept an album without both fields」證明兩個欄都冇都驗得過。Mutant M23（`buildDocument` 兩個欄都唔出）只有 `catalogRebuild.test.ts` 嘅完整物件比較捉到；validator 本身唔會擋。
- **影響**：而家 D1 兩欄都係 `NOT NULL`，所以 Backend 實際上一定會出。但「生成時一定行 validator」本來係最後一道防線，對呢兩個欄就冇咗。之後 seed（T-027）或者其他寫 catalog 嘅路徑漏咗呢兩個欄，都會照樣上線。developer 揀選填，只係因為播放端 fixture `apps/player/src/catalog/testing/catalogFixtures.ts` 唔喺佢嘅範圍。嗰個 fixture 得一個 `album()` builder，加兩個欄好細。
- **方案 A（推薦）**：兩個欄改做必填（型別同 validator 都改），拎走 `checkCategory` 嘅「兩個都冇」分支，`catalogFixtures.ts` 加 `category: 'album'`、`categoryNo`。代價：要改 `player-catalog` 鏈，要重驗 QA。
- **方案 B**：保留選填，但喺 Technical Spec API-072 寫明「v1 選填（兩個一齊有或者一齊冇），Backend 一定出」，開一行 backlog 等播放端 fixture 改好之後轉做必填。代價：合約變鬆，防線靠 D1 `NOT NULL`。
