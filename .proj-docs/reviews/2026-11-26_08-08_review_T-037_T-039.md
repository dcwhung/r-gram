## 🟡 Warnings

### W-049 【T-039】㩒過「立即更新」之後 `forced` 永遠係 true：reload 一被防 loop 擋，之後一次換版就會喺播緊歌時 reload（**must fix before QA**）

- **位置**：`apps/player/src/pwa/updateManager.ts:111-115`（`applyNow` 設 `forced`）、`:117-119`（`canApply`）、`:126-136`（`apply` 冇清 `forced`）、`:138-143`（`reloadOnce` 擋咗就靜靜雞 return）
- **L1**：Functional Spec US-011「播緊歌 / MV 時唔即時 reload」、D14「唔打斷音樂」；Technical Spec 實現注意事項 12
- **L2**（scratch probe P1）：播緊 → `handleNeedRefresh` → `guard.allow()` = false（30 秒內 reload 過）→ `applyNow()` → controllerchange：冇 reload（正確）。之後 `guard` 放行、仍然播緊、冇㩒任何嘢，再嚟一次 controllerchange（另一個分頁換咗下一版）→ **`reload` 叫咗 1 次**
- **L3**：要兩次部署好近（30 秒內）先會擋到第一次，但一擋到，呢個分頁之後成個 session 都當聽眾「已經同意打斷」。另外 `applied` 一直係 true，同一分頁之後嘅 `handleNeedRefresh` 全部唔理（新版要等第二個分頁或者重開 app）
- **方案 A（推薦）**：`forced` 只代表「今次」：`apply()` / `reloadOnce()` 做完（無論有冇擋到）就 `forced = false`；`reloadOnce` 被擋時連 `applied` 都還原，等下一個 `onNeedRefresh` 照規則再行。加測試 = P1。代價：幾行
- **方案 B**：`applyNow` 唔改狀態，直接叫一個 `applyForced()`，`canApply` 唔再睇 `forced`。代價：要重寫 `handleNeedReload` 入面 `applied && canApply()` 嗰段，測試要跟住改
