## 你問嘅幾點（W-005）

- **Probe 做法**：可以。`padding` 用 `env()`、JS 讀計好嘅 px 係常見做法；probe 掛喺 `body`，唔影響 React 管嘅 `#root`。
- **Stylesheet 未載入**：正式 build 冇事：stylesheet 喺 `<head>`，module script 要等佢先執行（上面個實測就係呢個次序）。但如果 stylesheet 遲到（我試過將佢延遲 600ms 先插入），舞台會停喺 `offsetY` 0、`--stage-extra` 421，**之後唔會自己修正**，要等下一個 `resize`。見 S-024。
- **橫向嘅左右 inset**：唔處理係啱嘅。手機打橫會出「請打直」（T-039），舞台唔 render；平板同電腦冇左右 inset。「請打直」嗰個畫面自己要加左右 inset（Observation）。
- **`getSnapshot` 入面讀 computed style**：唔會 loop。每次 render 讀一至兩次，只計 style 唔計 layout；值冇變時字串相同，React 唔會再 render。成本在於每次都 `querySelector` 成個 document，見 S-024。

## Suggestion（新，入 backlog，唔 block）

- **S-023** `i18n/hardCodedText.ts:36-42`：所有檔都當 TSX parse。`.ts` 檔如果有 `<T>(x: T) => x` 或者 `<string>value`，會被當成 JSX，後面嘅中文註解變成 JSX 文字而誤報（`const id = <T>(x: T): T => x;\n// 註解一` → 報「註解一」）。只會誤報，唔會走漏。按副檔名揀 `ScriptKind.TS` / `TSX`。
- **S-024** `stage/useStageFit.ts:5-16`、`stage/safeArea.ts:12-20`：安全區只喺 `resize` / `orientationchange` 或者 re-render 時重讀。對 probe 加 `ResizeObserver`（padding 一變佢個 box 就變）就可以自己修正，亦唔使靠 iOS 喺轉向時 `env()` 同 `resize` 嘅先後次序；順手將 probe element 存起，唔使每次 `querySelector`。併入 B-011，真機時一齊驗。
- **S-025** `styles/global.css:26`：`#root` 嘅底色固定係 `--color-stage`（淺色）。之後 Preload（黑底）、歌單 / 歌書嘅暗層、MV 嘅淡白層都只蓋到舞台，iPhone 上下兩條安全區會仲係淺色；闊畫面兩邊亦由黑變淺色。建議改做 `background: var(--stage-backdrop, var(--color-stage))`，由場景設定。`black-translucent` 嘅狀態列字係白色，喺淺色底上面睇唔到，要真機確認。T-034 之前定。
