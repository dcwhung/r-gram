### 1.2 六個結論

#### ① 手勢入面靜音解鎖，1.5 秒後出聲：**得**；採用：手勢入面 `cue()`（靜音 `play()`）→ 停喺 0 → 落針 `play()`

- 1a 兩個模式都過，1c 用戶親耳聽到。產品嘅開場其實短過 spike：`tonearmMs` 650 + `needleDropMs` 160 = **810 ms**（spike 用 1500 ms），所以有餘裕。
- **1b 證明咗乜**：iOS 18.7 上，㩒完 1.5 秒內喺 handler 以外對一個新 element `play()` 都得（WebKit 將手勢嘅「暫時啟用」帶過 timer）。
- **1b 證明唔到乜**：① 更長嘅延遲（歌單收返 + 慢網絡 + 開場，或者將來改長開場）幾耐之內仲得；② 舊 iOS（16、17）——以前 WebKit 只將手勢帶過 1 秒以內嘅 timer；③ 中間有 `await`（例如等 `fetch`）之後仲得唔得；④ Android Chrome（佢有自己嘅 5 秒窗口，冇測）；⑤ 手勢係咪畀其他嘢「用咗」。spike 兩次都係先㩒 1b 再㩒 1a，1b 用新 element，所以冇受 1a 影響，但頁面之前有其他㩒掣。
- **決定**：產品**照樣喺手勢入面解鎖**。成本係零（反正要設 `src`），佢令出聲唔再靠一個未知長度嘅窗口，仲可以喺開場期間先載頭幾秒數據。
- **改良（唔係 spike 原樣）**：1a 落針時先 `currentTime = 0`，結果約 0.5–0.6 秒之後先再出聲（1.2 秒只行咗 0.56–0.63 秒），即係「唱針放低」同「出聲」之間有可聽到嘅延遲。產品改為：手勢入面靜音 `play()`，一 `playing` 就 `pause()` + `currentTime = 0` + 取消靜音（喺開場期間做完 seek），落針嗰刻只係 `play()`。element 一經手勢 `play()` 成功就一直解咗鎖（② 同鎖屏上／下一首喺手勢以外 `play()` 都得，證明咗呢點），所以落針嗰下 `play()` 唔需要手勢。呢個改良要喺 T-038 真機核對（U-24 ①）；唔得就退返 spike 原樣（1a 已證明得，只係有延遲）。

#### ② 鎖屏下同一個 `<audio>` 自動下一首：**得**；採用：`ended` handler 入面同步揀下一首、設 `src`、`play()`

- 兩個模式都得，畫面隱藏（鎖機）時都得；鎖屏上一首／下一首亦係同一條路（`play() OK（畫面隱藏）`）。
- 規則：`ended` handler 入面唔可以有 `await`、唔可以等 React render 或者 effect 先揀歌：下一首由一個**同步**嘅 resolver（隊列純函數讀 controller 嘅 snapshot）即刻畀出嚟。
- **限制**：spike 每首只播 10–25 秒，鎖機下一共換咗 3 次歌（分頁 2、App 1）。903-player 喺 iOS 見過「`ended` 嗰下系統收起 audio session，下一集播緊但冇聲」（佢哋改咗喺結尾前 1 秒換集）。我哋嘅數據唔支持要咁做（換歌全部得），而且提早換會切走歌尾，所以**照用 `ended`**；但列為新風險 R-030，T-038 真機核對「鎖機播完一整隻碟」（U-24 ②）。

#### ③ Media Session：**得**（metadata、上／下一首、拖進度、暫停）；**`play` action 從來冇收到**；採用：狀態跟 element 事件，唔跟 handler

**spike 做咗乜**（`spike/audio/mediaSession.ts`）：`setActionHandler` 五個 action（包括 `play`），每個 handler 喺做嘢之前先記低；冇設 `navigator.mediaSession.playbackState`；冇設 `seekbackward`／`seekforward`（所以鎖屏出上一首／下一首，啱）；`setPositionState` 跟每次 `timeupdate`。註冊冇失敗（冇 `handlerFailed`）。

**數據**：分頁：`pause` → `previoustrack`（佢自己 `play()`）→ `pause` → 10 次 `seekto` → **再一次 `pause`**。第二次 `pause` 之前冇任何 `play`，即係中間有嘢令佢再播，但 `play` handler 冇被叫；或者 iOS 對一個已經停咗嘅 element 再送 `pause`。App：上／下一首、`seekto`、最後 `pause`，同樣冇 `play`。用戶話鎖屏播放／暫停「有效」。

**可能原因**（數據分唔到邊個，三個都要防）：

| # | 假設 | 支持 | 反對 |
| --- | --- | --- | --- |
| H1 | iOS 自己恢復 element（預設動作），冇叫 page 嘅 `play` handler，例如 page 喺暫停後被暫停執行、系統直接恢復 media | 分頁記錄「pause → seekto × 10 → pause」中間有嘢再播過 | 903-player 喺 iOS 鎖屏有收到 `ms:play`（佢哋 log 有） |
| H2 | 冇設 `playbackState`：iOS 鎖屏嘅播放／暫停掣狀態同 element 對唔上，用戶㩒「播」其實送咗 `pause`（或者乜都冇送） | 903-player 有設 `playbackState`，而佢哋收到 `play`；spike 冇設 | 解釋唔到「有效」 |
| H3 | 用戶其實係用上／下一首（佢哋自己會 `play()`）或者返入 app 恢復，以為係播放掣 | 兩次記錄每次恢復前後都有 `nexttrack`／`previoustrack` | 用戶明確話播放／暫停有效 |

**T-038 一定要做**（全部唔靠 `play` handler 一定會被叫）：

1. `play` 同 `pause` 兩個 handler 都註冊（連 `previoustrack`、`nexttrack`、`seekto`）；`seekbackward`、`seekforward`、`stop` 明確設 `null`（鎖屏保持上一首／下一首掣）。handler 只註冊一次（controller 建立時），唔跟每首歌重設。
2. **播放 store 嘅狀態一律由 element 事件推動**（`playing`、`pause`、`ended`），唔由 handler 推動：系統自己恢復（H1）會有 `playing` 事件 → store 變返 `playing`；系統自己暫停（電話、Siri、拔耳機）會有冇人要求嘅 `pause` → store 當用戶暫停（升針）。
3. 每次 element 狀態變就設 `navigator.mediaSession.playbackState`（`playing`／`paused`；冇歌載入 = `none`）（H2）。
4. `setPositionState` 喺知道長度、`playing`、`pause`、`seeked`、換歌時設（唔使每個 `timeupdate`，iOS 自己推算；做法同 903-player `useMediaPosition`），值要夾喺 0 至長度之間，長度未知唔設。
5. `metadata`（歌名、`RubberBand`、碟名、封面 `thumb` 320 + `cover` 1200 連 `sizes`）喺換歌嗰下**同步**設（自動下一首喺 `ended` handler 入面），唔等 React effect。
6. 真機核對（U-24 ③）：鎖屏暫停 → 等 10 秒 → 鎖屏播放，返入 app 時唱臂、唱片夾、時間同實際一致；開住 Safari Web Inspector 嘅話記低有冇 `play` action。

#### ④ MV 音量：**Web Audio gain 得、CORS 啱**；**靜音掣唔得**；採用：音量同靜音全部用 GainNode，唔用 `video.volume`、`video.muted`

- **靜音掣做咗乜**：`videoGraph.ts toggleMuted()` 只係 `video.muted = !video.muted`。嗰個 `<video>` 已經 `createMediaElementSource()` 接入 Web Audio：WebKit 由 element 攞聲畀 graph 嗰度係喺 `muted`／`volume` 之前，所以改 `muted` 唔影響 graph 出嚟嘅聲。即係唔係 iOS 唔准靜音，係**接咗 Web Audio 之後 element 嘅 `muted` 冇作用**。
- `video.volume`「可調」（4e）：spike 只係寫入再讀返，冇聽過有冇變；就算 iOS 18.7 真係會用佢，接咗 graph 之後一樣冇作用，而且舊 iOS 係唯讀。**唔用**。
- **決定（T-061）**：
  - 電視音量旋鈕 = `GainNode.gain`（0–1，`setTargetAtTime` 短 ramp，避免爆音）。
  - 靜音 = gain 去 0，記住之前嘅音量；再㩒還原。唔掂 `video.muted`（一直 `false`）同 `video.volume`（一直 1）。
  - 所有平台一樣（電腦、Android、iPhone），唔再做「特徵檢測 → Web Audio → 靜音開關」三條路。冇 `AudioContext`（極舊瀏覽器）= 旋鈕 `aria-disabled`，MV 用系統音量照播。
  - `<video>` 永遠 `crossOrigin="anonymous"`：CORS 壞咗嘅話 MV 會載入失敗（睇得到嘅錯），唔會變成「有畫面冇聲」。
  - 每個 `<video>` element 只可以 `createMediaElementSource` 一次：電視用**同一個** `<video>` element 播所有 MV（`videoEngine` 擁有，T-060）。
- **側邊靜音撥掣（未答）**：iOS 17 起 Web Audio 預設跟靜音撥掣（`audioSession.type = 'auto'` 時當「環境聲」），即係撥咗靜音嘅 iPhone 上，MV（經 Web Audio）可能冇聲，而唱片（`<audio>`，唔經 Web Audio）照有聲。用戶冇報 4 項嘅撥掣測試，亦冇報 `audioSession` 開關有冇分別。**假設（未答之前照做）**：開電視嘅手勢入面，有 `navigator.audioSession` 就設 `type = 'playback'`（4h：iOS 18.7 有呢個 API），等 MV 同唱片一樣唔理靜音撥掣。只喺 MV 路徑設，`audioEngine` 唔掂。T-061 真機核對（U-24 ④）。

#### ⑤ 幀率：**模糊背景得（60 fps）**；**Preload 旗幟唔得（約 5 fps）**；採用：模糊用 CSS `filter: blur()`；旗幟改 WebGL（新任務 T-113）

**模糊**：SVG 濾鏡同 CSS `blur()` 兩個模式都係 60.1 fps、0 % 掉格。揀 **CSS `filter: blur()`**：① 同 Technical Spec「模糊層：唱片機層 `filter: blur()`」一致，唔使改 spec；② 唔使喺共用 `<defs>` 加 filter 同 id；③ 半徑可以直接寫 `calc(var(--u) * 20)`；④ 瀏覽器可以交畀合成層做。量度時主頁係靜止（未揀歌），而 MV 開住時唱片機本身係停（US-007：碟滑行停），所以呢個量度同真實情況一致。

| ④ `drawMesh`：30 × 40 = 1 200 格 × 2 = **2 400 個三角形**（畫面內約 1 400 個），每個：`save` → 砌三角形 path → **`clip()`** → `transform` → `drawImage`（由 497 萬像素嘅布料圖取一小塊）→ `restore` | 約 1 400 × 7 次 canvas 呼叫 ≈ 1 萬次／格；每個非矩形 `clip` 要整一個遮罩 | **主因** |

結論：主因係 ④ 每個三角形一個非矩形 `clip()` + 一次有仿射變換嘅 `drawImage`（Safari 嘅 2D canvas 喺 GPU 程序用 CoreGraphics 逐個做，每個 clip 都要光柵化一個遮罩），次因係 ② 每格重畫一張接近 500 萬像素嘅布料圖、再被 ④ 取樣。JS 數學（①③）唔係問題。旗幟 canvas 本身（786 × 1704 ≈ 134 萬像素）唔大，DPR 已經封頂 2，所以單靠降 DPR 幫唔到幾多。**影響唔止睇落卡**：每格 200 ms 全部喺主線程，Preload 期間 catalog 解析、驗證、React render 同進度線都被拖慢。

**方案**

| 方案 | 做法 | 預計效果 | 代價 | 工作量 |
| --- | --- | --- | --- | --- |
| A：調低 2D | 網格 30 × 40 → 15 × 20（三角形 ÷ 4）；布料圖用畫面解像度（× 0.728，像素 ÷ 1.9）；光暗圖細一半 | 估計 3–4 倍 → 約 15–20 fps（推算，未量） | 摺位見到三角形稜角；好大機會仍然 < 30 fps，要再做一輪 | 0.5 人日 |
| **B：WebGL（建議）** | 一個 WebGL canvas：布料圖（黑布 + logo）只畫一次、上載一次做 texture；網格 31 × 41 點每格由現有 `projectCloth()` 喺 CPU 計（1 271 點，約 0.3 ms），`bufferSubData` 上載位置；光暗喺 fragment shader 逐像素計（`sumWaves`／`shadeAt` 移植做 GLSL，常數由同一個 TS 物件生成，唔寫兩份）。一次 `drawElements` 畫晒 | 60 fps 有餘（GPU 對呢個份量好輕鬆）；光暗仲會比 90 × 120 光暗圖幼細 | 新增 shader code（jsdom 測唔到 shader，要靠截圖比對）；要處理 `webglcontextlost`；冇 WebGL 要有後備 | 2.5 人日 |

### 2.2 型別同成員

```ts
/** 引擎只需要知嘅嘢：id 對返 store，url 已經逐段 encode（catalog selectors） */
export interface EngineTrack {
    readonly id: string;
    readonly url: string;
}

export type EngineErrorReason =
    | 'blocked' // play() 被拒（NotAllowedError）：要下一次用戶手勢
    | 'network' // MEDIA_ERR_NETWORK，或者重試用晒都未出聲
    | 'decode' // MEDIA_ERR_DECODE
    | 'unsupported'; // MEDIA_ERR_SRC_NOT_SUPPORTED（包括 404）

export type EngineEvent =
    /** 真係出緊聲（落針之後；靜音預備期間唔發） */
    | { type: 'playing'; trackId: string }
    /** 停咗。requested = false：唔係我哋叫嘅（鎖屏由系統處理、電話、Siri、拔耳機） */
    | { type: 'paused'; trackId: string; requested: boolean }
    /** 大約每 0.25 秒（timeupdate）；靜音預備期間唔發 */
    | { type: 'time'; trackId: string; positionSec: number; durationSec: number | null }
    /** 自動下一首已經換咗（喺 ended handler 入面同步做完） */
    | { type: 'advanced'; trackId: string; previousTrackId: string }
    /** 播完而冇下一首（resolver 回 null） */
    | { type: 'ended'; trackId: string }
    /** 想播但等數據超過 STALL_NOTICE_MS；之後出聲會有 playing */
    | { type: 'stalled'; trackId: string }
    | { type: 'error'; trackId: string; reason: EngineErrorReason };

export interface AudioEngine {
    /**
     * 只可以喺用戶手勢（click／pointerup／keydown handler）入面同步叫，之前唔可以有 await。
     * 設 src、muted = true、play()（= 解鎖 + 開始載入）；一出 playing 就 pause()、currentTime = 0、muted = false，
     * 停喺 0 等 land()。舊歌即刻停（唔發 ended）。
     */
    cue(track: EngineTrack): void;
    /**
     * 唱針放低：由 0 出聲（play()）。預備未完成（未出 playing）就記住，一出 playing 即刻出聲（唔再 pause）。
     * 未 cue 過 = 唔做嘢。減少動態效果：controller 喺同一個手勢入面 cue() 之後即刻 land()。
     */
    land(): void;
    /**
     * 即刻出聲播 track（冇開場）：鎖屏上一首／下一首、Repeat One 由頭。手勢入面或者 element 已解鎖都得。
     */
    playNow(track: EngineTrack): void;
    /** 繼續（升針 → 落針、鎖屏 play）。仲喺預備（未落針）= 同 land() 一樣 */
    play(): void;
    /** 我哋要求嘅暫停（paused 事件 requested = true）。預備期間 = 取消未做嘅 land() */
    pause(): void;
    /** 跳位置（夾喺 0 至長度）；metadata 未到就記住，到咗先套用 */
    seek(positionSec: number): void;
    /** 停同放開：pause()、removeAttribute('src')、load()（唔用 src = ''）；之後 Now Playing 冇嘢 */
    stop(): void;
    /**
     * 自動下一首嘅來源：ended handler 入面同步叫，回 null = 隊列完（發 ended）。
     * 一定要同步、冇 I/O（隊列純函數讀 controller 嘅 snapshot）
     */
    setNext(resolve: (currentTrackId: string) => EngineTrack | null): void;
    subscribe(listener: (event: EngineEvent) => void): () => void;
    /** 測試同 Media Session 用；畫面唔可以讀 */
    readonly currentTrackId: string | null;
    readonly positionSec: number;
    readonly durationSec: number | null;
}

/** 唯一入口：成個 app 一個引擎、一個 element（唔放入 React tree，唔會因為 unmount 而換 element） */
export const createAudioEngine = (element: HTMLAudioElement = new Audio()): AudioEngine;
```

### 2.3 每個成員嘅合約

| 成員 | 合約 |
| --- | --- |
| element | 引擎建立一個 `new Audio()`，`preload = 'metadata'`，唔設 `crossOrigin`（唱片唔經 Web Audio，實現注意事項 2），唔放入 DOM，一直用到尾（實現注意事項 3）。測試可以注入假 element |
| 世代 | 每次 `cue`／`playNow`／重試加一；舊世代嘅 promise（例如換 `src` 引起嘅 `AbortError`）同事件一律唔理 |
| `cue` | 同步；設 `src` → `muted = true` → `play()`。`play()` 成功 + `playing` → `pause()`、`currentTime = 0`、`muted = false`（seek 喺開場 810 ms 入面做完）。被拒（`NotAllowedError`）→ `error: blocked`。**唯一要手勢嘅成員**；element 第一次成功 `play()` 之後解鎖一直有效 |
| `land` | 預備完 → `play()`（唔使手勢）；預備未完 → 設 `landPending`，`playing` 嗰下改為：唔 pause、`currentTime = 0`、`muted = false`。之後先發 `playing` 同 `time` |
| `playNow` | 同步設 `src`、`muted = false`、`play()`；冇預備、冇開場 |
| `play` | 預備中 = `land()`；停咗 = `play()`；被拒 = `error: blocked` |
| `pause` | 標記 `requested`，`element.pause()`；本身已經停咗都照發一次 `paused`（element 唔會再發 `pause` 事件，903-player S-643 嘅教訓） |
| `seek` | 夾喺 `[0, duration]`；metadata 未到記住目標 |
| `stop` | `pause()`、`removeAttribute('src')`、`load()`；唔發 `ended`；由佢引起嘅 `emptied`／`error` 唔理 |
| `ended` handler | 同步：`next = resolve(current)`；有 → 設 `src` → `play()` → 發 `advanced`；冇 → 發 `ended`。中間冇 `await`、唔等 render |
| 系統暫停 | 冇 `requested` 嘅 `pause` 事件 → `paused { requested: false }`。唔自動再播（前景用戶自己㩒；903-player 嘅「鎖屏 Play 後系統停就自動再播」暫時唔搬，等真機見到先加） |
| 系統恢復 | 唔係我哋叫嘅 `playing`（③ H1）→ 照發 `playing`，store 跟住變 |
| 卡住 | 想播（`play()` 之後、未暫停）而 `waiting`／冇進展超過 `STALL_NOTICE_MS`（4 s）→ 發 `stalled`；前景超過 `STALL_RETRY_MS`（8 s）→ 記低位置、重設 `src`、`seek`、`play()`；畫面隱藏時唔重載（903-player v1.20.8：背景重開 range request 會更差），等返前景或者鎖屏 `play` 先試；每首最多重試 `STALL_MAX_RETRIES`（2）次，之後 `error: network` |
| 錯誤 | `MEDIA_ERR_NETWORK` → 同卡住一樣重試；`DECODE`／`SRC_NOT_SUPPORTED`（404 都係呢個）→ 唔重試，即刻 `error`。鎖機自動下一首遇到錯誤：停（照 US-004「載入失敗」），唔跳去下一首（見開放問題 Q3） |
| 常數 | `STALL_NOTICE_MS`、`STALL_RETRY_MS`、`STALL_MAX_RETRIES` 放 `config/limits.ts`（唔係動畫，唔入 `motion.ts`） |

### 2.4 開場（落針出聲）合約

| 情況 | 手勢入面 | 之後 | 出聲時間 |
| --- | --- | --- | --- |
| 由泊位開始播（揀歌、未揀歌㩒唱片夾、拎住嘅碟入機、熄 MV 後再播、重開 app 後第一次播） | `controller.start()` → store `start`（`playing`，唱臂開場）+ `engine.cue(track)` + 開落針 timer | timer 到（`leadInMs()` = `tonearmMs + needleDropMs` = 810 ms）→ `engine.land()` | 唱針放低嗰刻 |
| 減少動態效果 | `cue()` 之後即刻 `land()` | — | 即刻（載到就出） |
| 暫停之後繼續（升針 → 落針） | `engine.play()` | — | 即刻（FR-040「即刻續播」；放低唱針 160 ms 只係畫面） |
| 開場途中暫停 | `engine.pause()` 取消 `land`；store `paused`（`user`），唱臂照 `useArmLeadIn` 規則行完轉入、停喺升針 | 再㩒 = `play()` = `land()` | 再㩒嗰刻 |
| 畫面隱藏時由泊位開始（鎖屏 play、`ended` 期間） | `playNow(track)`，冇開場 | — | 即刻 |

- **點解用「停喺 0」**：唔用 `volume`（iOS 舊版唯讀，18.7 有冇效未驗）；唔用「一直靜音播、落針先 `currentTime = 0` + 取消靜音」（1a 證明得但有 0.5–0.6 秒延遲，而且開場期間 `currentTime` 行咗，要另外隱藏 `time`）；用 `muted` 只係預備嗰一刹（1a 證明 `muted` 對冇接 Web Audio 嘅 `<audio>` 有效）。
- **落針 timer 放 controller，唔放畫面**：出聲唔可以靠 React render、effect 或者唱臂元件有冇 mount（拎住、MV、測試）。`leadInMs()` 係純函數，放 `components/tonearm/armPose.ts` 隔籬，同 `useArmLeadIn` 讀同一組 `MOTION` token，所以畫面同聲音用同一個數。`useArmLeadIn` 唔使改。
- 由手勢到出聲 = 810 ms（加歌單收返嘅時間係並行，唔加）；真機核對「針落即出聲」（U-24 ①）。

### 2.8 MV 音訊（T-060／T-061，另一個細介面）

```ts
/** T-060：電視嘅唯一 <video>（成個 app 一個，因為 createMediaElementSource 每個 element 只可以一次） */
export interface VideoEngine {
    /** 電視 mount 時將 element 放入電視容器（同一個 element 搬嚟搬去） */
    readonly element: HTMLVideoElement; // crossOrigin = 'anonymous'、playsInline、preload = 'metadata'
    /** 㩒 MV 掣（手勢入面，同步）：mvAudio.attach()、設 src、play()（gain 0），一 playing 就 pause() + currentTime = 0 */
    cue(url: string): void;
    /** 螢幕開機（crtOn 完）：gain 去旋鈕音量、play() */
    reveal(): void;
    play(): void;
    pause(): void;
    /** ■ 或者播完：pause()、removeAttribute('src')、load()；mvAudio.detach() */
    stop(): void;
    seek(positionSec: number): void; // 下面旋鈕：快轉／倒轉
    subscribe(listener: (event: EngineEvent) => void): () => void; // 同 audioEngine 一樣嘅事件型別
}

/** T-061：MV 音量（GainNode）。所有平台一樣；唔用 video.volume、video.muted */
export interface MvAudio {
    /** 有冇 AudioContext；false = 音量旋鈕 aria-disabled，MV 用系統音量 */
    readonly supported: boolean;
    /**
     * 手勢入面同步叫：第一次建立 AudioContext、source、gain（之後重用）；context.resume()；
     * 有 navigator.audioSession 就設 type = 'playback'（唔跟側邊靜音撥掣；未驗，U-24 ④）
     */
    attach(video: HTMLVideoElement): void;
    /** 0–1；setTargetAtTime 短 ramp（常數放 mv 嘅 config，唔係動畫 token） */
    setVolume(level: number): void;
    /** 靜音掣：gain 0，記住 level；false 還原 */
    setMuted(muted: boolean): void;
    readonly volume: number;
    readonly muted: boolean;
    /** 電視收埋：context.suspend()（唔 close，下次 attach 再 resume） */
    detach(): void;
}
```

- 電視升起時唱片：`controller.pauseFor('mv')`（唱臂泊位）；收埋之後唔自動續播（C8，已有）。
- MV 嘅開場（升起 800 ms + 開機 220 ms）比唱片仲長：同唱片一樣喺手勢入面 `cue`、開機先出聲；`video.muted` 對接咗 graph 嘅 element 冇效（4f），所以預備期間係 gain 0，唔係 `muted`。
